### When to use

- to show the status of an item, such as a row in a table.
- Use Warning for items that are waiting, such as Pending or Awaiting review.
- Use Positive for finished items, such as Resolved, and Negative for failed items, such as Rejected.
- Use Info for work in progress, and Update for items that were changed or are new.

### Where it goes

<p class="missing"><strong>Not available.</strong> Badge.intent.json has no placement (no source states it; nothing was invented).</p>

### When not to use

- as a button. A badge is not clickable. *(Figma names no alternative.)*
- as a tab or a filter. *(Figma names no alternative.)*
- for long text. Keep labels to one or two words. *(Figma names no alternative.)*
- Do not choose a Type for its color. Choose it for its meaning. *(Figma names no alternative.)*
- Do not change the color, padding or corner radius of a badge. *(Figma names no alternative.)*

### Best practice

- Use the same label for the same status across every screen.
- Write labels in sentence case, such as "In progress".
- Show only one badge per item.

### Variants

| Variant | What it is for |
|---|---|
| `type=Warning` | Figma: items that are waiting, such as Pending or Awaiting review. |
| `type=Positive` | Figma: finished items, such as Resolved. |
| `type=Negative` | Figma: failed items, such as Rejected. |
| `type=Info` | Figma: work in progress. |
| `type=Update` | Figma: items that were changed or are new. |
| `type=Neutral` | Renders the gray style (code). Figma does not describe a Neutral type. |

### Accessibility

- Renders a plain &lt;span&gt; with its label text, so the status is named in text and the badge is not focusable. ([src/components/Badge/Badge.tsx:20](https://github.com/YINMYOSU10/cozy-corner-design-system/blob/4fab5eb8099283d987dd4441eec2fe21df1c3420/src/components/Badge/Badge.tsx#L20))
